Koa · 一次请求的分工

一个请求进来，谁在处理它？

只看两件事：哪些步骤是所有接口共用的（中间件），哪些步骤只属于这个接口（handler）。 下面用两个真实接口对照，再看 /agent/chat 里数据是怎么一步步被改名、转发的。

01两个请求并排走：共用的一段，和各自的一段

左边三列被两个请求共用；右边最后一列，各自走各自的。

请求 ① 所有接口共用 ② 按路径分流 ③ 只有这个接口走
App 请求/getSwiper Koa 公共步骤 解析 JSON
日志 / 耗时
错误兜底 		Router 看 App 请求的路径（如 /agent/chat），决定去哪个 handler getSwiper 的 handler 查 swipers 表 → 返回 JSON
App 请求/agent/chat verifyToken(false)agentChat 验身份 → 改名 → 转发给 Agent → 把 SSE 写回去
这一段两个请求都走 = 中间件
这一段只有 /agent/chat 走 = 路由自己的处理

verifyToken(false) 本身也是一个中间件函数，但它只挂在这一条路由上，所以只对 /agent/chat 生效；agentChat 是这条链的终点（handler）。 这里的“路径”指 App 请求 Koa 的路径（:3000/agent/chat）； Koa 再调 Agent 的 :8000/agent/chat/stream 是 handler 里自己拼的地址，Router 不参与。

02进到 /agent/chat 里，数据怎么一步步变成 Agent 的请求

盯着左边“谁”，看右边“数据长什么样”。

App
{ message: "深夜伤感的歌", sessionId: "mobile-1", turnId: "t-9" } + authorization: JWT
1公共步骤：解析 JSON，ctx.request.body 里就是上面这个对象；message 为空则直接 400。
Koa
ctx.request.body = { message, sessionId, turnId } ctx.user = undefined ← 还没验身份
2路由前置：verifyToken(false) 解 JWT；成功就把用户挂上，失败也放行（让 handler 决定怎么回）。
Koa
ctx.user = { id: 2, username: "user1" }
3handler 翻译：agentChat 把字段改名，并把用户 id 放进请求头，fetch 到 Agent。
Agent
POST /agent/chat/stream { query: "深夜伤感的歌", session_id: "mobile-1", turn_id: "t-9" } X-User-Id: 2
4handler 写回：Agent 边算边发 SSE；Koa 不拆开看，把字节块原样写给 App。出错/超时 → event: error。
App
event: status data: {"text":"正在理解…"} event: status data: {"text":"正在检索…"} event: result data: {"type":"songs","songs":[…]}
App → Koa──▶POST /agent/chat + JWT
Koa → Agent──▶POST /agent/chat/stream + X-User-Id
Agent → Koa → App◀──event: status（多次）+ event: result（一次）Koa 只转发，不解析

03所以，什么时候写中间件，什么时候写 handler

中间件handler
它服务谁所有请求，或一组路由只这一个接口
它关心什么请求的“公共部分”：解析、日志、身份、错误兜底这个接口的“业务部分”：校验、改名、转发、收尾
写在哪app.use(...)，或路由参数里 verifyToken()路由的最后一个函数 agentChat
一句话：这段逻辑是不是 /login、/getSwiper、 /agent/chat 都要？是 → 中间件；只有 /agent/chat 要 → handler。
