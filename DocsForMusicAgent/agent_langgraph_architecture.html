四个节点

guard

只做预算检查：取消、45s 截止、20k tokens、5 步。命中任意一条就产出 degraded 并去 finalize；否则放行到 llm。

llm

只调模型：call_model 追加 AIMessage、记录 tokens 和 tool_calls。没有 tool call 时交给 classify_no_calls（text / refusal / no_finish）。

tools

共享的工具派发：handle_tool_calls 执行 7 个工具、更新白名单/候选/约束；finish / ask_user 直接产出 output。

finalize

唯一的出口：degraded 兜底、finalize_and_save 组装 output 并写回 MySQL；取消的轮次不写会话。

图外：prepare_run

会话锁、载入 state、turn_id 幂等、Fast Path、pending 种子、拼 messages。完成后再 invoke 图。

图外：Fast Path

仅“无历史 + 精确歌名/歌手”才走；直接 finalize，不经过模型。这是设计里的确定性例外。

为什么不是 create_react_agent / ToolNode：我们的工具会顺手更新领域状态（白名单、候选、约束、pending）， ToolNode 只执行并追加消息；这些副作用必须写在自定义节点里。共享的 run_support.py 让手写循环和这张图用同一份工具派发和护栏，改一次两边都生效。
代码：agent/core/graph_loop.py（图）、 agent/core/run_support.py（共享运行时）、 agent/core/agent_loop.py（手写对照）、 agent/tools/agent_tools.py（7 个工具）。 验证：37 tests · hand/graph 各 30/30 golden · e2e 各 13/13 · degraded 0。
