**全部达标。** 且三类合并 Hit@5 都高于最强基线（test: B1=0.61、B2=0.78）。

> **F1 口径更正（2026-10-14，二次）**：上一轮把 absent 的 37 条**合并**成「曲库外歌词拒答 0.892」并宣布闭环，**系误读**——按子类拆分实为：**点名类 17/17 = 1.00**、**曲库外歌词 16/20 = 0.80**（低于曾定的 ≥0.85）。根因：单一阈值分不开（曲库外名句与库内中文转述的正确命中挤在同一分数带 [0.7,0.9]）。
> **新方案**：在意图解析里让模型**认出处**（`Intent.lyric_source`，Melo 式曲库反查）——认得出且歌名+歌手在库→正常作答并置顶；**认得出但库里没有→拒答“这句出自 X《Y》，曲库里没有这首歌。”**；认不出→才走置信度阈值。阈值只再管**冷门**曲库外歌词，已用新增 30 条冷门子类重新标定并**冻结为 `LYRIC_MIN_CONF=0.74`**（库内 lyric Hit@5 0.92 / 冷门拒答 19/30）。
>
> **F1 终结（2026-10-14，三次）——认出处方案未过留出集，已按 §7 回退固化**：dev 上该方案成立（库内 0.92 / 知名 0.95 / 零误认），但只跑一次的留出集（40 条）否掉了它——**库内歌词 Hit@5 0.75（线 0.88）**、**库内被误认成知名歌 2 条（线 ≤1，即预设的回退触发条件）**、知名拒答 0.80（线 0.90）。2 条误认是库内歌的歌词本身在引用真实传统曲/名曲（模型认出的是那首真歌，反查不在库 → 把库内正确歌拒掉）。已回退：`LYRIC_SOURCE_ENABLED=False`（代码保留、默认关闭）+ `LYRIC_MIN_CONF=0.75`。
>
> **最终固化数字（dev / 留出集）**：点名类拒答 **1.00**；知名曲库外歌词 **0.70 / 0.70**（线 0.90 ✗）；冷门曲库外歌词 **0.633 / 0.80**（不设线）；库内歌词 Hit@5 **0.88 / 0.85**（留出集线 0.88 ✗）；库内误认 **0 / 0**（结构性）。**未达标项如实留档。** 回退的取舍：库内 +0.10、知名 −0.10；知名 6 条漏召的置信度全在 0.75 之上，属“信号本身不够用”，非调参可解。漏召细分、留出集本身的构造缺陷（10 条“知名”是拿歌名当歌词喂的）、dev 知名 0.70 与架构师所得 0.80 的 2 条差异（意图提示词新增 `lyric_source` 段导致 LLM 输出变化，非代码回归），全部详见 `phase3loop.md` 末节「F1 二次落实」。**F1 已终结，不再迭代。**

## 3. 数据流（固定流水线）

① 意图解析（DeepSeek JSON + 快速通道；标签按 C3 词表校验、**语言归一成 ISO 代码**）
→ ② 多路召回（BM25 歌名+拼错 fuzzy；歌词中英双语 BM25+向量；semantic；similar）
→ ③ 融合/过滤/重排（**歌词类直接用歌词召回顺序**；其余 RRF + 硬约束过滤 + bge-reranker-v2-m3 重排 + 命中歌名置顶）
→ ④ 校验/放宽/拒答（固定放宽顺序，人声/语言/时长不放宽；点名查不到或歌手不匹配则拒答）
→ ⑤ 回复（DeepSeek 只写理由；song_id 越界即丢）。

## 6. 已知局限

- **ASR 歌词不可检索**：170 首 ASR 歌词（C4）不进歌词检索，用户搜这些歌的歌词会搜不到。
- **评测集偏小**：dev 109 / test 74；constraint、mood、describe_fuzzy 仅 dev。
- **mood 标注不中立**：0/1/2 在 `semantic ∪ agent` 候选池上打的，两个被评方法都贡献了候选；完全中立需人工标签（`semantic_labels.jsonl` 仍空）。describe 类查询是照卡片摘要生成的，与向量卡片同源。
- **本机 CPU 推理**：正式实测（2026-10-14，25 条 dev 查询，模型预热后）——冷缓存 mean 3.63s / P50 4.32s / **P95 5.00s** / max 5.63s，**达标 P95 ≤ 6s**；命中磁盘提示词缓存时 P95 2.98s。单条 **2 次 LLM 调用 / 约 1400 token**，歌名快速通道 0 次调用（0.06s）。未测并发与服务冷启动首条（约 45s，加载模型）。
- **F1 未达标（已终结）**：知名曲库外歌词拒答 **0.70**（线 ≥0.90）、库内歌词 Hit@5 留出集 **0.85**（线 ≥0.88）。试过的「认出处 + 曲库反查」在 dev 上成立（库内 0.92 / 知名 0.95 / 零误认）、在留出集上失效（库内 0.75、**误认 2 条**）→ 按预设规则回退。**这组双目标用现有信号拿不到**：知名 6 条漏召的置信度全在 0.75 之上，属信号本身不可分，非调参可解；另有 2 条漏召是**意图分类失败**（没判成歌词类查询，阈值降为 0.30）。明细见 `phase3loop.md` 末节「F1 二次落实」。
- **Lyric Hit@1** 0.83–0.88（Hit@5=1.0）：正确歌几乎总在前 5，但排不到第 1 的情况仍有约 1/6。
- 消融在 36 条子集上做（全量太慢），是相对量级。
